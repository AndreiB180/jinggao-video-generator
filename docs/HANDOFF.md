# 开发交接：2026-10-13（2026-10-14 晚更新到 v0.3）

## 先理解产品要求

目标是可交付的软件，主要输入中文文案，可选批量，自动生成常见营销号视频。不是人工逐镜精修一个样片，也不是继续展示“搜索到多少候选”。题材需逐步覆盖军事、历史、科普、美食、日常生活等。

硬目标：约四分钟成片，从开始处理到完整导出不超过 600 秒；每条目标成本不超过 0.10 元。当前只实现了模型费的 0.10 元限制，百度一镜价格未核明，完整成本尚未证明。保留费用账本，重试不清零，不把失败稿克隆成新项目重新花一毛钱。

最新质量标准优先于历史提示和旧测试：**普通画面只要大致相关、看着自然、没有明显错配即可；具体具名人物须确认。** 普通设备型号、年份、地点、动作、流程阶段不逐字追求完全一致。明确人工指定的画面要求保留。人物身份靠来源文字和画面姓名等依据核对，不靠脸部相似度。继续处理明显跑题、严重遮挡、广告、黑屏以及字幕同步问题。

默认 720p 以上、真实视频时长至少 80%，横竖屏支持。**2026-10-14 客户放弃百度一镜（Windows 上打不开一镜专用浏览器），配音改为千问配音 qwen3-tts-flash**，见下文“v0.3”一节。主要模型渠道为阿里云 Qwen，一个模型 API Key 即可配置核心模型流程；素材站 Key 可选。

## 这份代码是什么

`jinggao/`、`launch.py` 来自实际运行的 v60 冻结快照，源码哈希在 `source-baseline.json`。前端源码、依赖清单、构建脚本和测试从同一工作区收集。原工作区混有早期实验版，不能拿其根目录后端当成 v60；本仓库已处理这一点。

没有复制原机器的数据库、账号、API Key、百度登录态、素材、录屏、模型权重、费用账本或研究日志。文本测试夹具包含受控响应和历史公开素材观察，用于回归；它们不能当作新的模型验收结果。字体与字幕权重需要按 README 安装。

开发目标机器是通过远程连接访问的德国 Mac。中国来源和百度登录在该网络上的可用性必须实际验证。客户端界面可走 SSH 本地端口转发，不需要把无认证后台公开到互联网。未来客户交付仍是 Windows x64；德国 Mac 上能启动不代表客户 Windows 已验收。

## 已有的实质改动

- v60 在规划、素材库排序、在线排序、文字复核、最终选片中统一普通相关背景政策；具名人物和明确人工要求继续严格。
- 素材初筛补上按批共享的完整原稿与要求。之前本地排序只见“骑车”“出门”等短句，甚至没看到全文中的“自行车”，容易选到摩托车后再花钱拒绝。
- 原稿与实际语音在本地对齐，字幕按完整句子/分句组织；修改画面不应重新生成音轨。
- 已下载素材、本地索引、相同像素观察和原稿复核有缓存；模型账本在发送前预留费用。
- 新增免费本地音频定位：最多给两个合适的公开视频取小音轨、做本地 ASR，帮助选择原有四个采样点，不额外增加付费看图点。它只负责找位置，不批准画面。

## 下一步最值得处理的瓶颈

1. **可用素材时长和分配。** 港口首轮看了 16 个来源，但仅 8 个成功得到帧，共 25 帧。定位模型对 27/28 镜给出了建议，71 条建议中的 53 条集中在两条约 15 秒 / 19 秒的 Pixabay 短片上。大量“匹配建议”因此无法提供足够、不重复的真实片段。初步离线重放显示，不考虑来源否定时仅 7 镜可分配，补查后约 10 镜。这是阶段诊断，不能当全流程精确因果证明；但优先级明显高于继续微调普通语义拒绝条件。
2. **普通片段的审核开销。** 本轮联合像素观察约 0.036758 元，定位像素观察约 0.015255 元，场景排序约 0.014823 元，文字证据复核约 0.012246 元。需要按用户的新标准评估哪些普通镜头的重复检查可以合并，具体人物保留严格确认。仅把输出状态改成通过或降低真实费用记账都不是优化。
3. **来源可用性。** 首轮 B 站匿名搜索多次超时，部分平台验证或冷却，候选数量不能代替真实可下载且够长的素材供应。已取得的短片再好也不能假装填满四分钟。

用户已要求停止本轮调试并交给 Claude。交接时没有继续付费测试，也没有把上述两个优化设想伪装成已经完成的实现。

## Express 快速流程（2026-10 接手后新增，当前默认）

`config.pipeline` 默认 `express`（可切回 `classic` 走上面的 v60 流程）。目标是把每条约四分钟的视频压到 10 分钟内、模型费远低于 0.10 元，普通画面“大致相关”即可，具名人物须是本人真实影像。

| 模块 | 作用 |
| --- | --- |
| `express_plan.py` | 本地按句切镜（不改原文），一次便宜文本请求给出分组、B站中文/Pixabay英文检索词、每镜画面建议和必须出现的人物 |
| `express_sources.py` | B站匿名搜索、预览雪碧图、DASH 分段下载（每 256KB 检查一次取消/超时）；Pixabay；B站扫码登录（可得 720p+） |
| `express_match.py` | 联系表选片（Qwen 视觉）、按“车道”分配时间窗、三轮下载+成片抽检、人物车道、写入 `shot.frame_crop` |
| `express_clean.py` | 本地去水印/挡字幕：检测台标、B站上传水印、片源字幕、画面中部“@某某”水印、静止图片，输出安全裁切和模糊滤镜 |
| `media.py` | `render_shot` 对视频素材套用 `express_clean.video_filter(shot["frame_crop"])` |

### 去水印 / 挡字幕的做法

- **片源固定标记**：取 B 站预览雪碧图（约 100 帧/张、480×270）里互不相同的帧求中位数，风景被平均掉，固定叠加物保持锐利；再在实际下载片段的抽帧里确认（模式命中 ≥30% 帧才算）。
- **B站上传水印**（用户名+“bilibili”）只烧在 DASH 视频里、雪碧图里没有：对顶部 96px 的中位数图在左右上角做多尺度（0.6–1.3）归一化互相关模板匹配，阈值 0.62（实测有水印 0.68–0.98、无水印 ≤0.52）。
- **片源字幕**：画面下 30% 内居中的高对比亮笔画行，最多两行，须出现在 ≥45% 帧中，且相邻帧笔画掩码 IoU ≥0.75（真字幕 0.94–1.0，浪花/集装箱 ≤0.27）。字幕只裁不糊；裁不掉的片段标记为脏片。
- **安全裁切**：在去黑边后的内容区里找避开所有标记的最大输出比例矩形，放大不超过 1.42 倍；剩余角标用 boxblur 模糊。
- **画面中部水印**（如“@视效素材库”“月色梦光影”）裁不掉：须在 ≥20 张不同预览帧出现、宽 ≥0.12、宽高比 ≥2.5 才算；斜体/细笔画被拆成几段时按同一行拼接（`_join_line`），拼接结果须有 ≥40 张不同预览帧才采信，此时形状放宽到宽 ≥0.08、宽高比 ≥1.8。有此类标记的来源在预览阶段就降级（有 ≥2 个干净来源时不进选片联系表，分配代价 +6），实在要用时模糊并标记。
- **只在部分片段出现的半透明频道名**（如“项老说”）预览图里没有、本地也难以区分纹理，交给成片抽检：提示词明确要求列出这类水印，位置为中间/左侧/右侧时标记为脏片优先换片。
- **静止图片**：相隔约 1 秒的抽帧中变化 >20 的像素 <0.4% 视为冻结，≥55% 步冻结即判为静态图片（幻灯片照片）。
- **固定机位**（球馆、演播室）：片段帧与中位数的平均差 <15 视为固定机位，此时画面里常驻的广告板、栏杆、长椅和台标一样“不动”，片段内常驻笔画只采信紧贴角落的小标记；预览中位数检出的标记只接受叠加物常见位置（紧贴角落、顶部/底部横条、贴边竖条或侧边面板、够宽的一行字），画面中段的小块视为场景。B 站上传水印模板匹配和成片抽检不受影响。
- **成片抽检**：Qwen 看已裁切后的 3 帧，`wm` 返回全部位置（列表，左上/右上/…/左侧/右侧/中间），角落/顶部/底部一起再裁，中间/两侧标记脏片；带水印或静止的片段先作“暂定”，下一轮找干净、会动的替换，最后一轮仍找不到才接受暂定片段。同一轮里干净片段先于带标记片段处理。
- 裁切参数写在 `shot.frame_crop`，并用 `shot.crop_asset` 绑定测量时的素材；用户改选其他素材后不会套用旧裁切（隐私处理生成的派生素材仍沿用）。

### 字幕与分镜（2026-10-14 起）

- 字幕每次只显示一行。`subtitle_style.py` 按设置决定字体、字号、颜色，并算出一行能放多少字（`line_chars`，横屏默认 20 个全角字宽，数字/字母按半宽计）。
- 快速流程分镜按“一行字幕一个镜头”切分（`express_plan.line_shots`）：句子超过一行时先在逗号/顿号处、再在词之间拆成长度接近的两段；不足约 4.5 个字宽的片段并入同段相邻片段，保证每镜配音约 1 秒以上。长稿上限 400 镜，检索规划每 100 镜一批并行请求。
- 字幕时间按每个字的本地识别时间计算（`captions.segments` 传入本镜口播和字符偏移），一行从镜头开始一直显示到下一行开始；旧缓存没有字符时间时按字数比例拆行。SRT 与画面上烧录的行完全一致。
- 字体（均为 SIL OFL，`scripts/fetch_font.py` 下载）：思源黑体 粗（默认）、思源宋体 粗、站酷庆科黄油体、站酷快乐体、思源黑体 常规。所选字体缺字时（如黄油体缺“晙”）该字自动改用思源黑体，不会出现方框。字号 60/72/84/96（以 1080 短边计，默认 84，约为旧版 1.8 倍），颜色白字黑边或黄字黑边，在“服务与设置 → 字幕样式”中调整。
- 分镜工作台：快速流程的镜头缩略图与预览直接显示去水印后的画面（与导出相同的裁切和模糊），下方说明裁掉/模糊了什么，可切换“原画 · 标出检测”查看每处台标、字幕、中部水印的位置和成片保留区域。

### 新闻选题与 AI 洗稿（2026-10-14）

- 左栏“新闻选题与洗稿”：新闻来自三处：新闻爬虫（“抓取最新新闻”）、粘贴新闻链接（`news.fetch` 用标准库解析正文块，只允许公网地址，逐跳检查重定向），或手动粘贴原文。选题保存在 `data/news.json`，按链接（无链接时按标题+正文）去重。
- 勾选后“洗稿并自动出片”：每篇建一个项目（`project.news` 保存原文），排进整片队列；`produce` 在文稿为空时先跑 `rewrite` 阶段，再规划分镜、配音、配素材、导出。“先看稿”则把原文放进文稿，由用户在文稿页点“AI 洗稿”后再生成。
- 洗稿（`rewrite.py`）是两次文字请求：第一次改写成口播稿（保留人名、数字、日期、引语出处，不加新事实；开头抛结果/冲突，结尾提问；每行一句、不超过一行字幕；篇幅约等于原文，受“口播最长”限制，按每分钟 235 字估算）；第二次逐句对照原文只找事实错误，返回“原句 → 修正”，在本地逐行替换，不允许整篇改回原文。前端显示修正了哪几处，以及原文里没有的数字，供人工核对。
- 模型：阿里云接口下洗稿默认 `qwen3.7-plus`（实测 flash 会写错比分/年份、把数字写成汉字；plus 每篇约 0.01–0.02 元），可在“按环节选择模型 → AI 洗稿改写”改成 `qwen3.7-flash`。费用计入该项目，整片任务内计入该任务预算。
- 新闻爬虫（`news_crawler.py`）：客户的“全平台新闻爬虫”（GitHub AndreiB180/news-crawler，`main.py` + `core/crawler.py` + `platforms/`）在“服务与设置 → 新闻爬虫”填目录后自动识别：
  - “抓取最新新闻”运行 `python main.py --limit N [--platforms …]`，读取本次新建的 `data/采集/采集_*/` 批次（`标题：…/原文链接：…` 头 + 分隔线 + 正文）。实测今日头条/腾讯/搜狐每平台 3 条约 2 分钟。
  - 勾选“让爬虫用通义千问写口播稿”时加 `--koubo --max-koubo 5`，并只通过环境变量 `NEWS_LLM_API_KEY / NEWS_LLM_API_URL / NEWS_LLM_MODEL` 把本工具的千问密钥和洗稿模型传给这一次进程，不写入爬虫的任何文件；爬虫的口播稿（`koubo/口播/口播_*/`，末行“百家号标题：”）随新闻导入。出片时这类新闻直接用爬虫口播稿，只再跑一次本工具的事实核对（`rewrite.from_crawler`）。实测 5 篇约 8 分钟。
  - “导入上次抓取结果”读取爬虫窗口里抓好的最新批次（及已有口播稿），不运行爬虫；打包版没有 Python 时只能用这种方式。
  - 爬虫仓库的改动（通义千问为默认模型、环境变量传入模型、GUI 首次运行读取示例配置、对应测试）在交付目录 `news-crawler-通义千问.patch`；部署密钥只读，需要客户自己提交到仓库。
  - 其他爬虫：填运行命令和结果文件（JSON / JSONL / CSV / SQLite），或让命令输出 JSON。
- 实测（中新网航展新闻，725 字，口播最长 1 分钟）：洗稿 7.7 秒、全流程约 150 秒、76 秒成片 22 镜、全部珠海航展实拍、项目模型费 0.0138 元（含洗稿）。洗稿核对仍可能出小错（如“16年后再次”被改成“继2016年后”），自动出片前如需把关请用“先看稿”。

### 工作台编辑（快速流程项目）

- 快速流程项目（`plan_info.mode == "express"`）里，改画面适配、素材起点、时长、画面标注、检索词等不再清掉快速通道结果（`curation.express_edit`），镜头保持已确认；改口播需重新确认；改人物/事件条件会清掉身份结论，需要重新匹配或填写人工核对来源。
- 手动从候选或项目素材选片（`curation.manual_pick`）视为用户确认：普通镜头直接可导出；要求具名人物的镜头仍需填写来源链接和核对说明。此前这两种操作会让导出要求付费的经典逐帧核验而被卡住。
- “自动生成整片”会重新匹配未确认的镜头，但不会覆盖用户手动选的片（`manual_choice`）；改了口播的镜头标记为需重新确认（`needs_source_check`），不会被批量确认自动放行；改人物时清掉旧人物的核对说明。

### 全片预览（导出前）

- 分镜工作台“预览全片”（导出弹窗里也有“先预览全片”）：按导出的时间线依次播放全部分镜，不用先合成。时间线来自 `GET /api/projects/{id}/film`，与 `media.render` 相同：每镜时长按 25 帧取整、整段配音时按累计起点切字幕，逐镜配音时每镜用自己的音频。画面用与导出相同的去水印裁切/模糊、完整显示时的模糊底、图片缓慢放大，字幕用导出字体。
- 播放器以配音为时钟：整段配音直接用音轨时间，逐镜配音按镜切换音频，无配音时用系统时钟。当前镜头和下一镜的视频同时加载（下一镜停在起点、隐藏），切镜时不黑屏；画面与配音偏差超过 0.3 秒会重新对齐，片段短于口播时停在最后一帧（与导出一致）。
- 实测：89 镜港口片任意跳转后画面与配音偏差约 0.05 秒；连续播放 74 次采样没有未加载的黑帧。快捷键：空格播放/暂停，← → 上一镜/下一镜，Esc 关闭；“编辑此镜”回到工作台并选中该镜。

### 文稿规范化（所有文稿，2026-10-14）

- `script_norm.normalize` 在分镜前把任何文稿（粘贴、AI 洗稿、爬虫口播稿）变成同一种标准：按语义的全角标点、列表编号口语化（第一，第二…）、明显同音错别字改正、一句一行。规范后的文本写回项目文稿，配音和字幕都用它；原稿存在 `script_original`，文稿页可恢复。
- 需要模型时才调用（几乎没有标点、空格或换行代替停顿、裸列表编号）：每 1200 字一块并行请求 qwen3.7-flash；只接受“去掉标点后除列表编号外每处改动不超过 4 个字、总改动不超过 3%”的结果，改成繁体的字会被改回简体，每处改字都列出来；阿里云内容审核拒绝（HTTP 400）的块会对半重试，仍被拒的块只做本地规范。标点齐全的文稿只做本地规则（空格变逗号、半角变全角、一句一行），不花钱。
- 实测范仲淹稿（3800 字无标点）：3 块约 10 秒，改正“七七枕路→饿殍枕路”“玩的→玩得”等；分镜从 325 镜（按原换行乱断）变成 269 镜（按标点断句），百度配音停顿自然。

### 选片质量与速度（2026-10-14）

- 古人（照相术以前，规划时 `plan_info.ancient`）：检索“姓名 电视剧 片段/纪录片”，挑选和抽检都接受画像、雕像、影视剧和动画里表现此人的画面；整篇是古代历史题材时，普通镜头也接受古装影视剧、情景再现和历史动画，只拒绝现代场景、别的朝代或外国、主持人讲解。领域词要求是宽泛领域（“宋朝历史”），不能是标题（“范仲淹荒政”）。
- 主持人讲解类视频：在下载前用预览帧筛查（每个视频 8 帧，每次 8 个视频，结果按视频缓存），以讲解为主的视频在还有其他来源时不进入选片；运行中同一来源因主持人被拒两个不同镜头后，分配时大幅降权。
- 静态插画/幻灯片（`still`）只作最后手段，先用邻镜已通过抽检的画面（同一视频的任意空闲片段，复用片段也再抽检）；抽检判为严重跑题、或古代题材里出现现代/别朝代/外国场景的片段不再“勉强保留”，宁可用模糊邻镜画面的文字卡（卡片只显示人名，不显示内部画面建议）。
- 黑屏/淡入黑场本地检测（`motion.dark`），直接判不合格。
- 提速：配音和对齐期间后台预先完成素材检索、预览下载和主持人筛查（`express_match.warm`，在同一费用范围内运行）；渲染并发默认 3。范仲淹 12 分钟成片从 20.6 分钟降到约 17 分钟（同机并行跑测试时测得）；德国网络下最大耗时仍是 B 站片段下载。

### 人物镜头

- 车道代价：`pick 0 / person 1.5 / person_near 2.5 / ctx 3 / topic 4 / neighbor 4 / near 6`；人物镜头用主题补位再 +5，避免“讲钱学森却放火箭”。
- `person`：同一人物组里其他镜头已选中、且标题含姓名的来源；`person_near`：这些来源中已用时间窗前后 ±12/24 秒的空闲片段。
- 来源标题含已知人名时也套用影视剧/朗诵/情景再现等过滤词（`DRAMA_WORDS`）。
- 所有候选都被抽检拒绝时的兜底（`keepable`）：黑屏、主持人/采访、动画、PPT、水印遮挡等（`BROKEN_REJECTION`）对任何镜头都不保留；人物镜头在“要求人物”角色下被拒的片段一律不保留（真实本人影像不论主题都会通过，被拒说明是别人、演员或坏片），只有背景车道（ctx/topic）或无影像人物的片段且理由不涉及身份（`IDENTITY_REJECTION`）才可保留，并标为 `not_shown` 而非 `supported`。
- 口播没讲逝世时，人物镜头不能用葬礼/遗体/追悼会画面。
- **找不到任何真实影像的人物**（如清代的马保子，所有候选标题都不含此名）：该镜按普通镜头处理，用相关背景画面补位，不再退成文字卡；抽检提示也改为“不要求出现此人”。
- 整篇领域词（`plan_info.domain`，如“乒乓球”）：规划时让模型给出，并自动补进每个非人物检索词；选片和抽检都会被告知“其他领域（电竞、别的运动、卡通、3D 渲染、片尾订阅页、排行榜截图）不选/不合格”。这是为了避免“世界排名”搜到 CS2 电竞排名、“看球”搜到板球。
- 抽检的人物要求按车道决定：只有 pick/person/person_near 且来源含姓名时才要求画面是本人，ctx/topic 等背景画面不会因“没有此人”被拒。

### 2026-10-13 修正的重要缺陷

- 每轮下载曾对**所有**镜头重新分配、下载并抽检（`pending` 未随轮次缩小），第 2、3 轮白白占满带宽并重复花抽检费，大量“下载超出本轮时限”即由此而来。现在每轮只处理未完成或仍为暂定的镜头。
- 下载不再在每轮截止时丢弃：未完成的片段继续下载到下一轮（`self.inflight`），该镜头在下一轮不再追加新下载；匹配结束时 `stop_downloads()` 统一放弃。B站 CDN 慢时（实测曾低至全机 ~140KB/s）旧逻辑会把几乎所有片段都在截止时丢掉，导致整片文字卡。
- 片段时长允许比镜头短 0.25 秒（渲染用最后一帧补齐），不再因 9.17/9.20 秒这类误差丢弃。

### 已知问题

- 跑多次选片差异较大；偶尔仍有人物镜头退成文字卡。
- Qwen 抽检偶发 HTTP 400（疑似内容审核），该批视为未抽检。
- 德国机器访问 B 站 CDN 很慢（未缓存约 100KB/s），耗时主要花在下载上；中国网络下应明显更快。
- 匿名 B 站多为 480p 以下来源；扫码登录后可取 720p+，尚未在验收中启用。
- 只在一两秒内出现的片源字幕（抽样 10 帧里只命中 1 帧）本地检测不到，靠成片抽检；放宽阈值实测会把集装箱堆场、碗沿等误判为字幕，所以没有放宽。
- 低对比度的大号半透明频道名（如“桥桥妈”）在预览中位数里可见但边缘太弱，降低阈值会误判固定机位视频的背景纹理，目前同样靠抽检。
- 新闻画面里左对齐的标题条（如“中国空间站…”蓝底两行字）不符合“居中字幕”特征，本地检测不到，需抽检列出“底部”。

## v0.3（2026-10-14 晚）：千问配音、音频成片、新首页、自动保存、去重复

**千问配音**（`jinggao/qwen_tts.py`，`tts_provider=qwen_tts`，新默认）
- 接口 `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`，模型 `qwen3-tts-flash`，用模型的百炼 Key（`model_api_key`）。返回 OSS 上的 WAV 地址（会过期），下载后用 ffmpeg 按顺序拼接，语速（`tts_speed` 1.0/1.1/1.2/1.3，默认 1.1）用 `atempo`。
- 单次最多 600 计费字符（汉字算 2），按句切成 ≤480 计费字符的段，3 路并发（8 路会 429），429/5xx 退避重试。qwen-tts / qwen-tts-latest 返回 404。
- 计费：0.8 元 / 万计费字符（≈0.16 元 / 千汉字），`tts_costs.speech_request` 内置这条公开价，按响应 `usage.characters` 结算。**配音单独预算**：`costs._reserve` 里 `category='tts'` 只受 `tts_daily_budget_cny`（默认 5 元）限制，模型的任务 / 项目 / 每日预算只算模型请求；`costs.summary` 新增 `model` / `speech` 两组数字，项目页费用条分开显示。
- 音色：`qwen_tts.VOICES` 37 个（解说 / 故事 / 方言 / 角色四组），默认 `Ethan`（晨煦，本地 ASR 复核 100% 一致，约 4.2 字/秒）。试听样音已生成并随源码放在 `assets/voices/*.mp3`（.gitignore 已放行），所以试听不花钱；缺失时 `POST /api/tts/preview` 生成一次并缓存在 data/voice-samples。
- `config.migrate()`（launch.py 启动时调用一次）把已保存的 `baidu_http` / `baidu_web` 改为 `qwen_tts`，并写 `tts_migrated=1`，之后用户再改不会被覆盖。百度代码仍在，界面已去掉一镜按钮和选项。

**音频成片**：上传角色 `source_audio`（`/api/projects/{id}/upload`，3 秒到 60 分钟，项目须无分镜）。produce 先跑 `transcribe` 阶段：本地 paraformer 识别 → `script_norm.normalize` 补标点 → 写入 `script`（原始识别文本存 `script_original`，标题取第一句）；规划后把上传的音频作为 `full_audio` 对齐，不再配音。

**自动保存**：每次 render 后 `media.deliver()` 把 MP4 复制到 `media.output_folder()`（设置 `export_dir`，默认 Windows「视频\镜稿成片」、Mac「影片/镜稿成片」），同名加（2）；SRT 放在子文件夹「外挂字幕（仅上传平台时用，播放时不要加载）」。`auto_save_exports=0` 可关。导出记录里有 `saved_to`。`POST /api/output-folder/open` 打开该文件夹。测试里 `tests/conftest.py` 的 autouse fixture 把 `export_dir` 指到临时目录（曾经漏掉过一次，测试往真实影片文件夹写了两个假视频）。

**前端**（`QuickStart.tsx` 首页、`ProduceView.tsx` 项目「成片」页、`WorksGrid.tsx` 我的作品、`VoicePicker.tsx`）：左栏改为 一键成片 / 我的作品 / 新闻选题 / 批量制作；首页是文案框（或音频拖放）+ 画面比例 + 音色（试听、语速）+ 字幕样式（字体 / 字号 / 颜色，带预览）+ 清晰度 + 开始生成（显示预计时长、费用、用时）。提交后进入项目「成片」页：五步进度 → 成片播放、下载 MP4 / SRT、打开成片文件夹、精修画面、再做一条。原工作台（文稿 / 分镜精修 / 素材 / 导出记录）保留。配色从橙色改为青绿，去掉了英文小标题和编号标签。`GET /api/projects` 现在带最新成片和最近任务状态。

**去重复**（`express_match.allocate`）：范仲淹改进版 269 镜只来自 42 个视频、单个视频最多 22 镜、43 处同一视频相隔不到 3 秒。现在：同一视频超过时间线 4%（`SOURCE_SHARE`）后每多用一次 +6 成本；相邻镜同源 +3（原 1.5）；同一视频两个窗口相距 < 8 秒 +2；窗口间最小间隔 1.5 秒（原 0.6）；每个 tile 记 dHash，和时间线上已选画面相差 ≤6 位（同一素材换号重传）+5；每个检索词取 B 站前 4 个（人物 5 个，原 3/4）。

## 本地素材库（footage_index，2026-10-14 晚）

客户问“是不是在 5 万条里循环”：快速流程从来没用旧版的 5 万条来源索引（那份只在原机器上，不在仓库），每条视频都现场搜 B 站 / Pixabay，所以来源少、重复多。现在加了只存索引、不下载视频的本地素材库：

- `jinggao/footage_index.py`，数据在 `data/footage-index.sqlite`（单文件，可在界面「素材库」导出 / 导入，`merge()` 只补对方有而本机缺的、或本机没描述过的视频）。
- 每个视频存搜索行（标题、标签、时长、UP 主、播放量）和 8–10 个“时刻”：B 站自带预览雪碧图里的帧（`videoshot` 接口 + CDN 图片），dHash 去重、去黑帧；用 qwen3.7-flash 看 24 帧一张的联系表，每帧一句描述 + 类型（实拍 / 影视剧 / 动画 / 图表文字 / 主持人出镜 / 黑屏或模糊）。实测每张联系表约 0.00066 元（每帧约 0.00003 元）；答案漏掉的帧再问一次。
- 检索：中文双字切分写进 SQLite FTS5（`terms` 表；标题行 t=-1，每个可用时刻一行），bm25 排序；主持人出镜过半的视频标 `host` 不参与检索，图表文字 / 黑屏 / 主持人的帧不进检索。
- 出片时 `express_match.search()` 先查本地库（不走网络），`candidates()` 每个检索词先取本地 3 个（`LOCAL_PER_QUERY`）再取 B 站现搜；带描述命中的视频加 0.6 分，`tiles_for()` 优先取描述命中的那几帧，所以联系表直接给到对应画面。用过的视频 `used` 计数（以后可用于跨视频去重）。每次出片现搜到的视频和帧时间也自动写进库（`add_seen`，只有标题文字，没有描述，下次批量扩充时补描述）。
- 批量扩充：界面「素材库」选题材包（`PACKS`：历史·宋朝、历史·通用、军事、科普·自然、城市·经济、美食·生活，每包 10 个关键词）或自定义关键词，后台任务 `footage_index`（挂在系统项目“素材库采集”上，和出片共用一个 worker，扩充期间出片要排队）。并发：B 站搜索 3 路（412 风控）、videoshot + 雪碧图 8 路、看图描述 6 路。费用记在 `footage_index` 类别，有单独的每日上限 `index_daily_budget_cny`（默认 2 元），不占模型预算。
- 实测：「历史·宋朝」10 个关键词、每词 20 条 → 收录 164 个视频、1386 帧，210 秒，0.039 元。
